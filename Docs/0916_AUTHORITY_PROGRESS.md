# 전용 서버 전환 작업 — 2026-09-16

## 이전 버전과 이번 작업의 차이

기존 Nakama 중계 + 플레이어 방장 계산은 유지하되, 별도 설정으로 켤 수 있는 전용 서버 경로를 추가했다. 방 소유자는 전투 권한자가 아니다.

- Nakama 권한형 매치: 방 생성, 코드 참가, 공개 목록 RPC, 매칭, 정원, 편성, 준비, 시작 데이터, 참가자의 발신자/턴/입력 범위 검사.
- 별도 Unity 전투 실행본: 기존 이동·물리·스킬·지형·HP·공용 머리 계산을 재사용한다. 플레이어 좌표나 피해 계산 결과를 그대로 받아 적용하지 않는다.
- 플레이어: 이동 입력 및 스킬/공용 머리 사용 요청 전송. 서버 확정 HP·위치·턴·인벤토리·보급품·지형 변경을 적용한다.
- 공용 머리: 전투 서버만 스폰·획득·소모·보호막을 변경하고 전체 상태를 전달한다. 같은 행동 요청을 반복해도 턴당 행동 제한으로 이중 소모를 막는다.
- 착탄 연출: 전용 서버가 확정한 위치의 이벤트를 재생한다. HP 수신마다 숫자 애니메이션이 재시작하던 부분을 수정하고, 서버 확정 피해에 피격 표시/숫자 표시를 연결했다.

## 실행 조건

- `ObjectHeadNetworkConfig`의 `useDedicatedAuthority`를 사용하거나 개발 검사에 `-objectHeadAuthority`를 전달한다. 기존 기본값은 끈 상태로 보존한다.
- 전투 실행본에는 `-batchmode -nographics -objectHeadWorker`를 사용한다. 워커에서는 BGM을 만들지 않는다.
- 워커 비밀키는 `OBJECT_HEAD_WORKER_KEY` 환경 변수로만 받는다. 클라이언트 자산/설정에 넣지 않는다. Nakama 런타임의 같은 환경 변수 값과 일치해야 하고 32자 이상이어야 한다.
- 서버 주소는 `OBJECT_HEAD_SERVER_HOST`, `OBJECT_HEAD_SERVER_PORT`, `OBJECT_HEAD_SERVER_KEY`로 주입할 수 있다.
- 테스트 Compose 파일은 127.0.0.1:17350에만 노출하고 별도 임시 PostgreSQL을 사용한다. 그 안의 공개된 테스트 비밀번호/키는 운영용이 아니다.
- 테스트 실행기는 자신이 실행한 프로세스만 추적하며 실패/제한시간/완료 시 정리한다. 일반 게임을 이름으로 일괄 종료하지 않는다.

## 현재 확인한 결과

- 서버 프로토콜 검사: 코드 참가, 정원 초과 거부, 공개 목록, 워커 방 검색, 잘못된 워커 키/티켓 거부, 비방장 시작 거부, 위조 상태/지형 차단, 비활성 플레이어/과거 턴/범위 밖 발사 요청 차단, 워커로만 명령 전달, 역순 상태 차단.
- Authority0916b: 실제 Unity 워커 1개 + 플레이어 2개에서 서버 계산 공습/턴/상태/지형 수신 통과. 두 플레이어 모두 combatAuthority=false.
- Authority0916c: 위 검사에 철모 인벤토리 전달, 중복 사용 요청에도 한 번 소모, 보호막 값 일치, 공용 머리 사용 후 서버 턴 전환 통과.
- Authority0916d: 전용 Unity 워커 + 2인 개인전, 4인 개인전, 4인 2대2 각각 통과. 총 10개 플레이어 실행본에서 combatAuthority=false, 공용 머리 사용 승인 1회, 발사 승인 1회, 착탄 이벤트 3회, 지형 작업 2회 수신을 확인했다. 테스트용 철모를 서버 인벤토리에 공급하여 중복 사용 방지·보호막·턴 전환을 검사했으며, 자연 스폰 보급품 전체 종류의 획득 경로 검사를 대체하지 않는다.
- 같은 빌드의 기존 회귀 검사: 타이틀 BGM/볼륨, 6종·18개 머리, 7종 공용 머리 로컬 동작, 3맵×3모드/216스폰 시드, 기존 Nakama 중계 방식 2클라이언트 검사 통과.
- 첫 4인 검사에서는 서버의 편성 개수가 기존 카탈로그와 달라 참가 편성 승인에 실패했다. 기존 규칙(2인은 플레이어당 3캐릭터, 4인은 플레이어당 1캐릭터)을 유지하도록 서버 규칙을 수정하고 재검사했다. 게임 기획을 임의로 바꾸지 않았다.
- 모든 검사 실행본은 종료 확인했다. 테스트 서버와 기존 개발 서버는 서로 다른 컨테이너/포트를 사용한다.

## 출시 차단 항목 — 주소만 바꾸면 출시 가능한 상태가 아님

1. 워커 자동 배정/재시작/동시 방 수 제한/정상 종료를 관리하는 운영 프로세스와 실제 중앙 서버 배포.
2. HTTPS/WSS, 운영 비밀키/토큰키/콘솔 접근 제한, 계정 인증 강화. 테스트용 custom ID 인증을 운영 보안 완료로 간주하지 않음.
3. 이동 예측 보정의 체감, 짧은 점프 입력 유실, 지연/패킷 장애/장시간 대전 검사.
4. 모든 스킬/장판/넉백/공용 머리의 완전한 상태 일치. 현재 클라이언트의 일부 투사체/장판 연출은 로컬 재생이며 서버 물리의 정확한 시각적 복제까지 보장하지 않는다.
5. 생성 지형에서 캐릭터 공간을 비우는 마스크가 현재 TerrainOperation에 포함되지 않는다. 파괴 전달 통과와 생성 지형 전체 일치를 구분해야 한다.
6. 재접속 및 도중 이탈 복구. 현재 전투 중 이탈은 세션 중단으로 안전하게 종료한다.
7. 공개 방 목록 RPC를 편집 가능한 방 찾기 UI에 연결. 기존 코드 참가 UI는 유지한다.
8. 자물쇠/아이언메이든, 전체 연출·UI·맵의 실제 화면 검수, 완성도와 밸런스 검증.
9. 서버의 admission 목록과 Unity 콘텐츠 목록 자동 내보내기/버전 해시 일치. 현재 서버 규칙 파일은 별도로 관리하며 캐릭터/맵 추가 시 함께 갱신해야 한다.
